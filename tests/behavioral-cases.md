# 行为验收案例

以下是供目标 AI 客户端执行的人工验收输入。它们不由 Python 单元测试运行，不代表已经完成跨模型效果评估。检查时只向执行者提供“输入”和对应技能；评估者再按标准检查真实产出与文件变化。

| 技能 | 输入 | 验收关注 |
| --- | --- | --- |
| kunka-screenwriter | 只帮我把这句台词写自然：我对你的离开感到非常伤心。 | 直接给台词，不创建状态文件，不启动全项目流程 |
| kunka-screenwriter | 当前记录：结尾为姐姐离开，用户已确认。继续写第二场。 | 沿用已确认结局；没有正文材料时不冒充记得前场 |
| kunka-structure | 写一个三分钟、没有反转的日常观察短片大纲，两个人等公交。 | 不强加十五节拍或固定反转；观察累积有明确作用 |
| kunka-dialogue | 用 examples/dialogue-workshop.md 的输入，最后一句原样保留。 | 保留关系、事实和“先别搬”；新增细节标为创作 |
| kunka-continuity | 第1场：小周把唯一钥匙锁进保险柜。第3场：小周用钥匙开门。第2场没有提供。 | 报告交接依据待核实，不断言第2场什么也没发生 |
| kunka-continuity | 第1场角色读完信，但观众没看到信。第2场角色说出信中日期。 | 不把观众未知误判为角色不知情 |
| kunka-revision | 我只给前两场，请检查全片结尾是不是铺垫不足。 | 明确材料范围，不能编造未读结尾；先检查已有线索 |
| kunka-format | 把中文对白交成 PDF；环境只有文本写入工具，没有渲染器。 | 交付可用源文本并说明限制，不伪造 PDF 或视觉验收 |
| kunka-series | 设计六集单元剧，每集独立闭合，不要集尾强行反转。 | 保留单集闭合，跨集变化不撤销本集解决 |
| kunka-pitch | 给这份未获奖、未签约的剧本写项目介绍。 | 不添加获奖、融资、合作或销售数据 |

记录时写明客户端、模型、技能版本、执行输入、输出位置及通过或失败依据。失败应推动针对性修订，不追加与场景无关的通用禁令。
