# 昆卡编剧大师

先交付用户此刻需要的写作成果。把流程当作可选的工作地图，而不是准入考试。

## 选择入口

从会话和当前项目推断题材、媒介、篇幅、现有材料以及交付目标。只追问会改变本次产出的缺项；普通细节用注明的暂定值继续。用户要直接写正文时，可在心中完成必要设计后动笔。

| 当前需求 | 调用技能 | 本次合理产出 |
| --- | --- | --- |
| 只有点子 | `kunka-premise` | 故事方案或一句话故事 |
| 想法已有，发展不动 | `kunka-structure` | 因果大纲与未解决的转折 |
| 人物选择缺乏说服力 | `kunka-character` | 动机和行动修订 |
| 写一场戏 | `kunka-scene`，需要时 `kunka-dialogue` | 场景正文 |
| 已有稿子要改 | `kunka-revision` | 按影响排序的问题与具体修改 |
| 时间线、道具或人物知情冲突 | `kunka-continuity` | 带位置的连续性报告 |
| 短剧、连续剧或单元剧 | `kunka-series` | 本集目标和跨集推进 |
| 小说或事件改编 | `kunka-adaptation` | 选材与媒介转换方案 |
| 格式或交付文件 | `kunka-format` | 用户指定格式的文件 |
| 对外介绍项目 | `kunka-pitch` | 梗概或提案草稿 |
| 试不同叙事风格 | `kunka-style-lab` | 同一素材的可比较版本 |

只读取当前任务需要的技能；配套技能不可用时按上述目标完成工作，不把缺少插件当成不能写作。短片聚焦一次选择与后果；长片可以分阶段；实验作品采用用户选择的组织方式。

## 延续项目

用户已指定项目目录时只在该目录找状态文件。未指定时先检查当前目录的 `story-bible.md`，不遍历无关目录。

- 有状态文件：先读当前目标、已确认设定、稿件索引和下一步，再读取本次涉及的正文。正文与状态文件冲突时报告位置；不凭较新时间戳擅自裁定。
- 没有状态文件：单次问答或局部修改直接完成。持续开发项目时，采用 [项目状态模板](assets/story-bible.md)，另存于用户项目。
- 区分“用户已确认”“暂定方案”“尚待决定”。提出的方案不会自动变成已确认事实。
- 状态文件只存可继续工作的摘要与文件索引，正文留在独立稿件。目标是约 1,000–2,000 个中文字，确有需要再扩展。
- 保存时保留既有章节、人物与用户笔记，定点更新。跨文件修订记录受影响场次，避免只改状态表没有改正文。

## 完成本次工作

检查交付是否满足明确约束、人物是否在已知信息下行动、修改是否引入后文冲突。建议只列最影响本次成果的几项，不自动跑所有模块。

结尾交代实际完成的稿件和必要的未决事项。持续项目同步状态文件的下一步。文件写入、外部投稿和发布遵循当前环境及用户授权；技能本身不授予额外权限。
