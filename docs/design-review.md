# 优化审视与设计取舍

日期：2026-09-10。版本：1.0.0。

## 基线

审视对象为 [screenwriting-skills](https://github.com/jtydhr88/screenwriting-skills) 的提交 `0657714b59c82d3d6656ada50c5168d4ea431de0`。读取范围包括仓库说明、完整目录、技能入口的元数据、章节与约束性规则，以及总流程和格式入口的具体内容。没有逐条核验全部书籍引文或原作分析。

该版本有 13 个 SKILL.md，入口正文连同前言共 307,081 UTF-8 字节；另有 222,581 字节的参考文件。单个入口最高 33,342 字节，部分触发描述超过 1,000 字符。

## 值得改进的地方

| 观察到的情况 | 实际影响 | 昆卡版处理 |
| --- | --- | --- |
| 触发描述同时罗列大量知识与出处 | 发现阶段负担大，技能分工不够清楚 | 使用简短、具体的中英触发描述，补充中文 UI 标题 |
| 入口包含大量理论、作品比较和引文 | 一次局部任务也可能读取大量无关材料 | 入口只留当前任务的决策方法；状态模板单独保存 |
| 一些写法被表述为绝对规则 | 容易误伤短片、观察型作品、群像和开放结局 | 明确用户形式优先，结构模板作为选择 |
| 总流程默认创建状态并推进固定阶段 | 一次台词修改可能被扩大成项目管理 | 局部任务直接完成，持续项目才记录状态 |
| 状态摘要容许接近一万五千汉字 | 续写时检索成本高，正文与记录容易重复 | 状态以约一至两千字为目标，正文单独存放 |
| 改稿与连续性分散在知识模块中 | 诊断可能停在一般建议，缺少两端证据 | 新增独立修订、连续性技能与位置化报告 |
| 剧集主要作为流程入口的一条分支 | 本集与季线职责不够明确 | 独立分集模块，区分单元、连续与混合形式 |
| 原仓库以 Claude Code 安装为主 | Codex 用户需要自行定位与复制多个技能 | 添加零第三方依赖安装器、可预览计划和备份升级 |
| 有中文 Fountain 指令，但未内置转换器 | 使用时仍需区分源文件与真实导出 | 保留强制标记要点，明确工具能力与真实文件检查 |
| 无标准开放许可证，含第三方作品表达 | 无法把整个旧包直接改挂 MIT | 重新编写内容并致谢，不携带摘录、译文和旧 Git 历史 |

## 模块变化

基础创作能力保留为构思、结构、人物、场景、对白、改编、格式和提案等任务入口。原版按国家、作家和作品组织的研究模块不在此版本重新发布；以原创风格实验承接表达手法比较，并腾出独立的改稿、连续性和剧集模块。

因此这是任务导向的新实现，不是内容等量的压缩版，也不宣称完整保留原项目的书籍知识。用户仍可独立保留原版 `sw-*` 技能；新版使用 `kunka-*` 避免同名覆盖。

## 可测量结果

- 新版 13 个入口共 26,653 字节，相比基线减少约 91.3%；最大入口为 3,246 字节。
- 所有技能有简短触发描述、中文 UI 元数据与可执行任务边界。
- 插件和安装脚本共享同一份技能源文件，没有两份需要手工同步的正文。
- 安装默认预检全部冲突；相同内容重复安装跳过；更新将原文件放入技能目录之外的备份。

字节数直接测量 UTF-8 文件，既不是 token 数也不是效果评分。新版删去了研究资料类别，因此减少体量不等于同内容压缩率。

## 验证与限制

发布前运行官方技能格式校验器、本项目结构与链接检查，以及安装器的独立临时目录测试。安装测试覆盖无写入预览、重复安装、预检冲突、备份更新、模拟写入失败回滚、符号链接拒绝、指定安装和锁冲突。

[行为验收案例](../tests/behavioral-cases.md) 是供实际客户端复测的输入及判定标准。它们不是已经完成的模型基准测试。此版本没有声称跨模型写作质量、商业成功或长篇连续性能力已经获得实证提升。

安装器支持一般异常回滚，不提供抵御断电或强杀的事务保证。格式模块提供源文本规范，不附带 PDF、FDX 渲染器。行业信息需要使用时核对现行官方来源。
