# 设计与维护

本说明面向维护者，介绍技能的组织方式、修改约定与验证方法。

## 技能组织

`kunka-screenwriter` 负责理解当前目标，并选择需要的专用技能。其他技能分别处理构思、结构、人物、场景、对白、改稿、连续性、剧集、改编、格式、提案与风格实验。

单场戏或局部润色直接处理当前内容。持续开发项目时，使用状态文件保存已确认设定、暂定方案、稿件索引与下一步；正文存放在独立文件中。

所有技能源文件统一保存在 `plugins/kunka-screenwriting/skills/`。Claude Code 插件从这里加载，Codex 安装脚本从这里复制，维护时只需修改这一份正文。

## 编写约定

- `description` 简要说明能力与适用场景，帮助客户端选择技能。
- `SKILL.md` 保留实际影响工作决策的方法；可选模板放在配套文件中，并注明使用时机。
- 用户已确认的人物、关系、结局和形式优先于默认写作方法。
- 审读意见提供位置、证据和影响；区分明确错误、缺少材料和风格建议。
- 格式交付与当前工具能力一致，转换文件后再核对实际结果。
- 新增规则应对应具体使用问题，避免因一次失败扩大所有任务的流程。

项目校验约定：技能描述为 15–240 字符，入口文件不超过 8,000 UTF-8 字节。这些是本项目的维护阈值，不是客户端通用限制，也不是写作质量指标。

## 修改与验证

```bash
python3 scripts/validate.py
python3 -m unittest discover -s tests -v
```

结构校验覆盖名称、元数据、链接和插件路径。安装测试覆盖预览、重复安装、冲突、备份、失败回滚、符号链接、指定技能和安装锁。

改动技能行为时，选取 [行为验收案例](../tests/behavioral-cases.md) 中相关的输入，在目标客户端检查实际产出。记录客户端、模型、技能版本和判定依据。自动校验与人工案例分别报告，不将格式检查通过表述为创作效果已获验证。

## 安装维护

安装器默认预检冲突；相同内容跳过；更新前将原文件备份到技能发现目录之外。一般异常会触发本次安装回滚，断电或强制终止后可能需要人工恢复。

完整操作见 [安装管理](installation.md)。修改安装逻辑时，应使用临时目录验证，不用个人技能目录测试失败场景。
